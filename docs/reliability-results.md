## Проверенные факты и доступность

- API и Worker восстановились автоматически после SIGKILL дочернего процесса Tini: container ID сохранился, RestartCount увеличился. Ручной Docker stop/kill не использовался для этих аварий.
- Во время падения единственного API были ошибки соединения. При остановленном первом Worker второй обработал новое событие; оба POST завершились 201. При `prefetch=1` одно сообщение может оставаться неподтверждённым у приостановленного consumer до его возвращения.
- При недоступном Redis GET вернул 200/BYPASS, POST — 201; после start кэш снова давал HIT.
- При недоступном PostgreSQL и удалённом ключе кэша GET вернул 503, `/health` оставался 200. После возвращения строка совпала с исходной.
- Перед рестартом RabbitMQ подтверждённое persistent-сообщение было unacked=1, ready=0 у приостановленных consumer; после рестарта — ready=1, unacked=0. После SIGCONT тот же уникальный ID появился в логах и снова подключились два consumer.
- Копия: 2643 байт. Restore создал только `seps_restore_8b2998ddd56a44f4`, восстановлено строк: 21. Содержимое marker `54b9dd56-144d-473f-8975-bf69ed50a9fa` совпало. Событие `5b20bec2-545e-4776-a3ee-aef767896566`, созданное после dump, отсутствовало в новой БД и осталось в production.

В коротком окне аварии API: 5 проб, 1 успешная, доступность 20%. Успешный GET занял 25.57 мс; при единственном успешном запросе p95 равен его задержке. Это окно намеренного сбоя, а не проверка 10-минутного SLO ≥99% и не подтверждение задержек под нагрузкой.

MTBF не измерен: нет длительного наблюдения естественных отказов. Среднее время нескольких искусственных аварий не выдаётся за статистически устойчивый MTTR. RPO=0 наблюдался для проверенной строки/сообщения при сохранных томах; ежедневное RPO ≤24 ч остаётся условной целью расписания, а потеря хоста не проверялась.

## Условия воспроизведения

- Все шесть сервисов работали до начала сценария. После каждого сбоя и в finally возвращены запущенные сервисы. Контейнеры PostgreSQL и RabbitMQ использовали существующие именованные тома; production не очищалась.
- При отсутствии cgroup freezer вместо Docker pause использовались SIGSTOP/SIGCONT процессов Worker. Глобальные firewall/sysctl Docker-хоста и Windows не менялись.
- Из-за лимита диска и VFS тестовые образы API/PostgreSQL/RabbitMQ уплощены export/import с сохранением rootfs и конфигурации образа. Все исходные Dockerfile собраны, firewall не отключался; обычный запуск проекта этого обходного шага не требует.
- Сессионный CA HTTPS-прокси передавался как BuildKit secret через локальный Compose override, не включённый в Git.
- Бинарные архивы и полный JSON-отчёт находятся в игнорируемых backups/ и reports/. Этот документ сохраняет только синтетические результаты, без дампов и паролей.
